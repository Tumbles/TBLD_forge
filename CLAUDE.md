# TBLD Forge

This repository is a fork of [Forge](https://github.com/Card-Forge/forge), the open-source Magic: The Gathering rules engine. It is being adapted to run TumbledMTG (TBLD), a custom constructed format with thousands of original, fan-made and modified cards and its own mechanics, and to let players play TBLD online in a browser with full rules enforcement and a chess clock.

## Working with Brett

- Be blunt and brief. State what changed and what he should do; leave out the reasoning unless he asks.
- When one clarifying question decides the answer, ask only that question.
- Test before handing anything over. Every feature must pass an automated test that exercises it (see "Tests") before Brett is asked to try it.
- Explain build and tooling steps plainly; Brett is not experienced with Java tooling.

## Decisions

- Architecture: our own server runs headless Forge; players use a browser client. A modified Forge desktop client remains a fallback.
- XMage and contacting the Endstep developer are backup plans only. Do not reconsider them unless Brett raises them.
- TBLD card script files are named with a `tbld_` prefix (e.g. `forge-gui/res/cardsfolder/tbld/tbld_searing_touch.txt`), matching the "TBLD " prefix in Brett's Cockatrice files. The displayed card name (`Name:` in the script) has no prefix and is exactly Brett's card name, which drops apostrophes and commas ("Lilianas Steward", "Sheoldred the Apocalypse"); a split card "Fire_Ice" is "Fire // Ice".
- Official cards are not in the pool; they are kept only as reference scripts for writing TBLD cards. Since 2026-11-26 the game loads only `forge-gui/res/cardsfolder/tbld/`; every official script is in `tbld-pool/reference/cardsfolder/`, which nothing loads. Tests and test decks use TBLD cards only. Upstream tests that use official cards no longer work.
- The whole pool comes from Brett's Cockatrice card files and is scripted in batches of Claude's choosing (see "Card pool"). His ability templating differs from Oracle wording; the `Oracle:` line is his text, word for word.
- Engine changes for TBLD rules are made directly in the Forge code.

## TBLD rules implemented

| Rule or mechanic | Implementation | Test |
|---|---|---|
| Flash is a supertype (replaces the flash keyword and the instant type) | `CardType.Supertype.Flash`; `Card.hasFlashSupertype()`; checked in `SpellAbility.withFlash` and `SpellAbilityProperty` ("CouldCastTiming") | `TbldFlashSupertypeTest` |
| London mulligan bottoms cards after the hand is kept (CR 103.5) | `LondonMulligan.keep()`; the keep prompt states the number of cards; `InputLondonMulligan` has no Auto button and ignores OK until enough cards are chosen | `TbldWebServerTest` |
| Starting emblems: the first player in turn order gets Player One, the next Player Two, and so on up to Player Five (two players: One and Two). Given once the starting player is chosen, before the opening hands. | `forge.game.tbld.TbldEmblems` (the five emblems as card scripts); on when `GameRules.setTbldStartingEmblems(true)` (the web server sets it); `GameAction.startGame`. Engine additions: the `ExileFromCommand<1/CARDNAME>` cost ("Exile this"; the emblem leaves the game), `CantBeCountered$ True` on an ability (`SpellAbility.isCounterableBy`, `CounterEffect`), `ExtraTurn$ False` on a BeginTurn replacement. Player One's emblem replaces the two-player rule that the first player skips their first draw (`PhaseHandler.isSkippingPhase`). | `TbldStartingEmblemsTest`, `TbldWebServerTest` |

| The first land a player plays in their first turn enters tapped | `Player.playLand`; on when `GameRules.setTbldFirstLandEntersTapped(true)` (the web server sets it) | `TbldPriorityAndPaymentTest` |

| Scan ("look at the top two cards of your library and exile one of them") | No engine change: scripts use `DB$ Dig | DigNum$ 2 | ChangeNum$ 1 | DestinationZone$ Exile | DestinationZone2$ Library | LibraryPosition2$ 0` | `TbldCardPoolTest` (cards build) |
| TBLD Clues (Investigate makes a Clue enchantment token with "2, Sacrifice this: Scan, then draw a card") | Token script `tbld_c_e_clue_scan`; TBLD cards that investigate create it with `DB$ Token`. Clue is also an enchantment type (`forge-gui/res/lists/TypeLists.txt`), so the token keeps its Clue subtype and "sacrifice a Clue" sees it | `TbldCardPoolTest`, `TbldMultiCards2Test` (Lazav Wearer of Faces) |
| Transmute exiles the card from your hand (not a discard) and has no shuffle; sorcery speed | `CardFactoryUtil` (`ExileFromHand<1/CARDNAME>`), `Keyword.TRANSMUTE` reminder text | `TbldBlueCards3Test` (Muddle the Mixture) |
| Ingest exiles the top two cards of the player's library (not one) | `CardFactoryUtil` (the Ingest trigger digs 2); `Keyword.INGEST` reminder text | `TbldBlackCards1Test` (Bearer of Silence) |

Not started: Journey, Upload, Spirited, Shift, Reflex, Crescendo, Experience, luck counters, modified voting, no planeswalkers, the TBLD life total and deck rules. Cards that need them are in `tbld-pool/blocked.txt`.

## Card pool

Brett's TumbledMTG card files, made for Cockatrice, are a card XML, a token XML (tokens, emblems and the back faces of double-faced cards) and a folder of card pictures. Brett maintains the card XML by hand; it is not exported from Magic Set Editor. Those files are the source of truth, and where a card's picture and its XML text disagree, the picture is right; the repository holds an imported copy. `tbld-pool/TbldPool.java` does the work; run it from the repository root with the JDK alone, no build: `java tbld-pool/TbldPool.java <command>`.

- `import` reads the three sources named in `tbld-pool/sources.properties` (`cards=`, `tokens=` and `pictures=` with local paths; the file is not committed, and the tool says how to write it when it is missing). It writes `forge-gui/res/tbld/pool/cards.txt` and `tokens.txt` (one `[Name]` block per card, sorted, text on one line with `\n`), and reports cards added, removed and changed since the last import, duplicate entries, and scripts that no longer match. Pictures become JPEG files (quality 0.9, at most 375 x 523) in `forge-gui/res/tbld/pics/`, named "TBLD <name>.jpg"; `tbld-pool/pictures.txt` records each source's hash, so only new or changed pictures are converted and pictures whose source is gone are deleted. Pictures matching no card are listed, not imported. `pictures.extra=` (folders separated by `;`; on Brett's PC his Dropbox "For Reddit" and "Split Cards" spoiler folders) only fills gaps: a card or back face with no picture in the main folder. A picture there wider than tall of a double-faced card shows both faces side by side, and is split into the card's picture and its back face's. `tbld-pool/corrections.txt` ("Name | field=value") corrects the XML where a picture disagrees with it (Fathom Feeder costs UB; "Brutal Brutal Subjugation" is Brutal Subjugation; a text value writes a line break as `\n`); import warns when the XML no longer needs a line.
- `status` counts scripted, out-of-date and unscripted cards. `list` prints one line per card, filtered (`--todo`, `--auto`, `--color R`, `--tag GOBLIN`, `--type Creature`, `--text REGEX`, ...). `show NAME` prints a card's pool entry, its script's differences and its official reference script with both texts normalised side by side.
- `draft NAME...` writes `tbld_<name>.txt` from the official script of the same name: name, cost, type line, P/T and Oracle from the pool, `K:Flash` dropped when the type has the Flash supertype, everything else kept. It says whether the texts match; if not, the abilities must be edited by hand. `draft --auto` drafts every card whose text matches its official card's once both are normalised (`brettify` turns Oracle wording into Brett's: symbols without braces, "this" for the name, "into play" and "in play", "gain" for "you gain", flash sorcery for instant, "this turn" for "until end of turn", "at your upkeep" for "at the beginning of your upkeep", no planeswalkers, "Can't be activated at flash speed" for "Activate only as a sorcery", tokens without the word creature; reminder text dropped). Cards whose type line has a misspelt card type are not drafted; `import` warns about them. Cards with several faces, and cards with no official script, are written by hand.
- `check` (run by `TbldCardPoolTest`) fails unless every TBLD script matches its pool card exactly (Name, ManaCost, Types, PT and Oracle; Brett's cost "1W/B" is `1 WB`, "2/W" is `2W`, "H/U" (Phyrexian) is `UP`; his type "Creature - Elf" is `Creature Elf`), no official script shares a TBLD script's name, and the TumbledMTG edition lists exactly the TBLD scripts. `edition` rewrites the edition: collector numbers already given are kept, new cards get the next number, basic lands are P1-P80, I, S, M, F and W (Wastes has 3).
- Basic lands: the pool has "Mountain1" to "Mountain80" and so on; one script per basic (`tbld_mountain.txt`), its versions listed in the edition in order, so version N is art index N.
- Scripts that do almost, but not exactly, what Brett's text says are listed in `tbld-pool/approximations.txt` ("Name | difference") for his review.
- `verify` sorts every non-basic pool card into implemented, scripted but untested, placeholder or blocked, and prints the counts (`--list KIND` prints names). Implemented means its abilities are played by an automated in-game test (the names in `tbld-pool/verified.txt`, which must equal the card tests' `VERIFIED` lists, collected in `TbldVerified`; `TbldCardPoolTest` checks both) or it has no abilities at all. Scripted: a script matching the pool with ability lines for its text that no test plays yet (copied from the official card with the same text, adapted by hand, or possibly incomplete: fewer ability lines than paragraphs of text, instants and sorceries counted as one). Placeholder: no script, an out-of-date script, or a script without ability lines. Never call a card implemented, or a batch done, unless a test plays its abilities. Counts on 2026-11-28: 455 implemented, 722 scripted but untested, 1,418 placeholders, 35 blocked. How to verify a batch: `tbld-pool/VERIFYING.md`.
- Verifying scripted cards: batches of about 50 cards of one colour (black first, then multicolour, then the rest), alphabetically, skipping cards without a picture. Each batch is a test class `Tbld<Colour>Cards<N>Test` extending `TbldCardTest`, with one test per card that plays every ability and checks the result against Brett's text; its `VERIFIED` list goes into `TbldVerified.LISTS` and `tbld-pool/verified.txt`. A script that fails is fixed, not the test.
- Cards that can't be scripted yet go in `tbld-pool/blocked.txt` ("Name | reason": a TBLD mechanic the engine lacks, or a problem in Brett's data); the tool shows them as blocked and leaves them out of the to-do lists (`list --blocked`).
- Hand-adapted scripts (`draft` when the texts differ, then the abilities edited to Brett's text) are checked by the tests only for loading, linting and being buildable as game objects, not by playing them (so `verify` counts them as scripted, not implemented); Brett reviews cards later through a pool-editing workflow. TBLD tokens that differ from Forge's (Brett's Goblin tokens "can't attack or block alone", for one) are token scripts named `tbld_...` in `forge-gui/res/tokenscripts/`.
- Batches so far: every card whose text matches its official card once normalised; then the red cards with an official reference but changed text. Then the green and white ones. Next: blue, black, multicolour and colourless changed cards (`list --ref`), then originals (`list --noref`), then multi-face cards and the TBLD mechanics.
- After Brett changes cards: import, then `status`; fix each out-of-date script (`show` it), draft or write the new ones, run `check`, then the tests.
- Known pool problems (reported by every import): misspelt types on Indebted Spirit ("Enhantment"), Eater of Virtue ("Legnedary") and Bludgeon ("sorcery"), so they stay unscripted; Zada Hedron Grinder's type ends in "4". Dustpit is in the card XML twice with different text (the first is kept); Disconnect and Torment of Scarabs twice with the same text; Shapeshifter and Squirrel twice in the token XML. Phyrexian Bauble's cost "H" (generic Phyrexian mana) has no Forge equivalent. Adventure cards have no name for their adventure half in the XML.

## Web play

- `forge-gui-desktop/src/main/java/forge/tbld/server/TbldWebServer.java`: Netty HTTP and WebSocket server. Serves the client at `/` and one WebSocket per seat at `/ws?seat=N`. Starts a two-player match once both seats connect: seat 1 plays the red TBLD test deck (`testDeck()`: goblins and burn, Mountain version 69), seat 2 the green one (`greenTestDeck()`: wolves, hydras and pump, Forest version 11). Every card in them has a picture and its abilities are played by `TbldTestDecksTest` (Rodeo Pyromancers and Thrashing Brontodon, which have no pictures, were swapped for Crackling Cyclops and Greenweaver Druid on 2026-11-27); further seats alternate. Tests can give every seat one deck (a `Supplier<Deck>`). `{t:"restart"}` from either browser abandons the match and starts a new one.
- Test decks (`TbldTestDecks.ALL`, 40 cards each, only implemented cards with pictures): red and green (above), and since 2026-11-28 blue-black counterspells, blue-red spells, white-blue heroic flyers, white-black life drain, black-red aggro and black zombies, none sharing a card with red or green. A seat picks one in the client's settings ("Deck"); `{t:"deck", id}` sets that seat's deck and starts a new match. The browser remembers its choice per seat in `localStorage` and names it when connecting (`/ws?seat=N&deck=ID`, used only before the match starts), so the choice survives a server restart. `hello` carries `decks` (`id`, `label`) and the seat's current `deck`.
- `BrowserSeat.java`: one seat in one match. It implements Forge's `IRemote` under a `ProtocolGuiGame`, so every engine call on the player's GUI (`ProtocolMethod`) arrives here.
  - Before each call it sends `{t:"state", state}`: a full snapshot filtered to what that player may see. Each visible card carries its face (name, cost, type, text, power/toughness, colors, set, and `img`, a picture URL when there is one), and cards named in calls carry the same face when the player may see them, so popups can show them. The snapshot also has `phaseId` (the `PhaseType` name) and, for each stack item, `ability`, `trigger`, `controller`, `targets` (names) and `targetCards` and `targetPlayers` (ids), gathered from the item and its sub-abilities (Stand Together's "another target creature" is on its sub-ability).
  - Then it sends `{t:"call", m, a, rid?}`. Calls with a `rid` block the engine until the browser answers `{t:"reply", rid, v}`; `v` is an index or an array of indices into the offered options.
  - Clicks arrive as `{t:"act", m: "ok"|"cancel"|"card"|"player"|"stack"|"mana"|"undo"|"concede", id}` and run on the seat's own thread. They must not run on the Netty thread: an action can make the engine ask the same player a question, and the answer arrives on the same connection.
  - Answered on the server without asking the player: combat damage assignment (all to the first blocker), dividing damage or counters, sideboarding, `manipulateCardList`. `getAbilityToPlay` with one playable ability uses it without asking.
  - `order` (Forge's dual list, used for scry, surveil, "choose N cards" and ordering) is answered with indices into the source list followed by the destination list, in the chosen order.
  - The server sets `FPref.UI_SELECT_FROM_CARD_DISPLAYS` off, so cards are picked by clicking the board only on the battlefield and in the player's own hand. Choices from other zones (a library, an opponent's revealed hand, scry) come as dialogs, which the client shows as popups of cards.
  - In the snapshot, a blocker's `blocking` names the attacker it blocks, and an attacker's `blockedBy` lists its blockers; `blockingIds` gives the ids of the attackers it blocks, for the block lines. Until blockers are declared, Forge's `CombatView` holds the chosen blockers only as planned blockers (`getPlannedBlockers`), and `isBlocking` is false; the seat shows planned blockers to their controller only.
  - `{t:"pref", autoPass, holdPriority}` sets the seat's priority settings, each as a `YieldUpdate.SetYieldPref` override on its controller (that seat only). `autoPass` is `"off"`, `"manaOnly"` or `"noActions"` (`true`/`false` mean manaOnly/off). Both on modes use Forge's "auto-pass if no actions" (`FPref.YIELD_AUTO_PASS_NO_ACTIONS`), which ignores mana abilities, so manaOnly passes when the player could only tap for mana; noActions also sets the TBLD pref `YIELD_AUTO_PASS_COUNTS_MANA_ABILITIES`, with which an activatable mana ability (an untapped land, the Player Two emblem) counts as an action (`PlayerControllerHuman.manaAbilityCountsAsAction`). `holdPriority` false sets the TBLD pref `YIELD_HOLD_PRIORITY` off: after the player casts a spell or activates an ability that uses the stack, they pass priority (`PlayerControllerHuman.playChosenSpellAbility` and `chooseSpellAbilityToPlay`), unless a triggered ability went on the stack above it (Crackling Cyclops's trigger from casting a spell): then they get priority, as Brett asked; the switch governs only responding to their own spell or ability. A trigger they always yield to (see "Always yield") doesn't give them priority: they pass over it and, once it has resolved, over their own spell. The client sends both on connect and on restart, remembered per seat in `localStorage`; defaults: auto-pass manaOnly, hold priority off. Seats that never send them (the test bots) have auto-pass off and hold priority on. The seat also turns off Forge's yield interrupts on an opponent's spell and on being attacked, so "Yield all" passes everything.
  - "Yield all" is Forge's pass-until-end-of-turn yield. `{t:"act", m:"yieldAll", id: 1|0}` turns it on (passing priority now if the player holds it) or off (`autoPassCancel`); End Turn turns it on too. While an action can be undone, Forge's priority prompt puts Undo where End Turn was; the client then shows OK, End Turn (which sends yieldAll 1) and Undo, so End Turn never moves. The snapshot's `yieldAll` says whether it is on; it ends with the turn.
  - "Always yield" (as on MTGO, Brett asked 2026-11-28): each triggered ability on the stack has `yieldKey` (the source's name and its ability text, `PlayerControllerHuman.yieldNameKey`, so it covers every card of that name; Forge's own key names one card) and `alwaysYield`. `{t:"act", m:"alwaysYield", key, on}` switches it, as Forge's per-card auto-yield (`YieldUpdate.CardAutoYield`): while on, the player passes priority whenever that ability of that source is on top of the stack (`PlayerControllerHuman.skipsPromptForStackOrPhase`); switching it on while they hold priority over it passes now. It is only switched on for a trigger the player can see on the stack. The snapshot's `alwaysYields` lists those switched on (`key`, source `name`, `text`); Forge forgets them when the game ends.
  - Paying: when the floating mana covers a whole cost, it is spent without a payment prompt (`InputPayManaOfCostPayment`). Optional costs such as buyback (`PlayerControllerHuman.chooseOptionalCosts`) are offered only when the player can pay them (counting lands, other mana sources and the pool, as Forge's AI would pay); with none affordable there is no question. Otherwise it is a single choice from a list: each affordable combination, then "No buyback" (or "No optional costs"), with only a Confirm button.
  - `{t:"pref", stops: {own: [...], opponent: [...]}}` names the phases (`PhaseType` names) in which the player stops for priority on their own turn and on an opponent's turn. For every other phase in `BrowserSeat.STOP_PHASES` the seat sends `YieldUpdate.SkipPhase`, so Forge passes priority there while the stack is empty; with something on the stack the player still gets priority. Seats that never send stops (the test bots) stop everywhere.
  - Each player's `counters` (energy, poison and so on) are in the snapshot by name (`{"Energy": 2}`).
  - The log in the snapshot is the last 100 entries, oldest first.
  - Each player's `command` zone (emblems and lasting effects) is in the snapshot. An emblem's `type` is its printed type line ("Emblem — Book of Lore", `TbldEmblems.typeLine`); a card with no printed text (an effect) gets its abilities' text. Forge's actionable cards (`AvailableActions`, which also decides "auto-pass if no actions") include the command zone, so a usable emblem is highlighted and counts as something to do. The Player Two emblem's mana counts like any other mana source for what can be cast (so two Mountains and the emblem make Rodeo Pyromancers castable), but the Auto payment button and its preview never spend a person's emblem (`ComputerUtilMana.sparingPersonsEmblems`, used by `InputPayMana`); they click it themselves. Auto starts disabled when the spell is payable only with the emblem and turns enabled once they have clicked the emblem and what is left of the cost is payable (`InputPayMana.activateManaAbility` rechecks the Auto plan after an emblem is used or when it was unpayable; Brett, 2026-11-28).
  - `getAbilityToPlay` (`BrowserSeat.sendAndWait`) follows Forge's desktop client (`CMatchUI.getAbilityToPlay`): when the engine asks without a click, as it does when it puts a triggered ability on the stack (`PlaySpellAbility.chooseOptionalAdditionalCosts`), a single ability is used as it is, playable or not; only for a click are unplayable abilities left out. Until 2026-11-27 the seat always left them out, and triggered abilities never count as playable, so every trigger a person controlled was dropped (Brett found it with Rodeo Pyromancers, Jungleborn Pioneer, Servant of the Conduit and Searing Blood); the engine tests with AI players did not show it. `TbldWebTriggersTest` covers it.
  - Activating an ability whose cost sacrifices its own source (a Blood token) does not ask "Do you want to sacrifice ...?" (`HumanCostDecision.visit(CostSacrifice)`, as Brett asked); a sacrifice paid for an effect ("unless ...") is still confirmed.
  - `-Dtbld.debug=true` logs every prompt, button change and selection to standard output.
- Declaring blockers (`InputBlock`, changed for TBLD in all clients, as Brett asked): select one of your creatures, then the attacker it blocks; after that nothing is selected. Selecting an attacker with no creature chosen does nothing. Selecting a creature that is blocking takes its block back and does not select it. Selecting the chosen creature again cancels the choice.
- `forge-gui-desktop/src/main/resources/tbld/web/index.html`: the client. One self-contained file of plain HTML and JavaScript, with its own visual design (Endstep was a feature reference only).
  - Board: the opponent's half on top, this player's at the bottom with their hand. Each battlefield has two rows, both centered: creatures in the front row (nearest the middle); in the back row lands, then other permanents after a gap. Two rows rather than three, to keep cards large; the back row has room because identical lands are stacked (same name and state); a stack of 4 or more shows its count in a badge under it, as Brett asked (7 or more until 2026-11-28). Tapped and untapped lands share a stack, tapped ones at the back, so tapping the top land leaves the next untapped one under the pointer (Brett taps a pair with two clicks on the same spot). Tapped lands lie along the bottom of the stack from the top untapped land's left edge and stick out to the right, so they form an L with it (as Brett asked); the stack's width does not change when lands are tapped. Every tapped card in the back row (a lone land, an artifact too) lies on that same baseline, so tapped cards line up (Brett, 2026-11-28). Auras and equipment are tucked behind what they are attached to. Rows overlap their cards when crowded.
  - Cards are pictures, turned sideways when tapped. TBLD cards load from this server (`TbldPictures`: `res/tbld/pics/`, served at `/pics/<file>`); official cards from Scryfall by name (`BrowserSeat.imageUrl`). A token gets the picture of Brett's token of the same name and colors from `res/tbld/pool/tokens.txt` ("Merfolk Token" is Brett's "Merfolk", "Merfolk2" and so on; one with the same power and toughness is preferred, then the lowest number; `TbldPictures.tokenUrlFor`). Brett asked for no Claude-drawn card mockups: a card with no picture (or whose picture is loading or fails to load) is a plain dashed placeholder with its name and "no picture" (`noPicture`), and its hover preview lists its type, power/toughness and text. Test decks hold only cards with pictures (`TbldTestDecksTest` checks).
  - TBLD card pictures are named as in Brett's card files: "TBLD Searing Touch.jpg" (the pool tool imports them; see "Card pool"). A card with several versions has one file per version, numbered by art index: "TBLD Mountain69.jpg"; a file without a number serves every version. A split card's file is "TBLD Fire_Ice.jpg". The server remembers which files exist, so restart it after adding pictures.
  - Basic lands: TBLD has 80 versions of each basic land (Wastes 3). The `TumbledMTG` edition lists each 80 times, Mountain with collector numbers M1 to M80, so art index N is version N (`Mountain|TBLD|69` in a deck). In game every version is just "Mountain", and versions stack together on the battlefield; the version number is only for places where it matters, such as a deck builder. About half the versions have pictures. The test deck's Mountains are version 69.
  - A player's counters are pills beside their life total: energy yellow with ⚡, poison green with ☠, others by name (Brett found energy from Servant of the Conduit was not shown).
  - Summoning-sick creatures are dimmed with a "zZ" badge; attackers move toward the middle with a red tag, blockers have a blue one; power/toughness and damage are badges. The power/toughness badge shows the creature's toughness unchanged by damage (a 2/3 with 2 damage reads 2/3, as Brett asked); the damage is its own badge. Counters are one chip each, stacked up from the card's bottom-left corner, never cut off with an ellipsis (Brett, 2026-11-28): +1/+1 and -1/-1 as short text with the count ("3 +1/+1"), names of up to four letters the same way, and everything else, keyword counters first, as a symbol (✈ for flying, and so on; the initials when there is none) whose label shows on hover (`counterChip`, `COUNTER_SYMBOLS`). The blocking tag says just "blocking"; the attacker is in its hover text and the block line.
  - While a cost is being paid, the Auto button sits in the player's bar, between the hand and the lands (Brett asked, to cut mouse travel); Cancel stays in the decision panel. Decision buttons carry the class dbtn wherever they are.
  - The space bar confirms the open popup (a hidden popup is shown first) or presses the decision panel's main button (OK, pass priority, Keep). After a button is pressed, the buttons are disabled until the engine sends new ones (or for one second if it sends none), so a quick second press can't pass the next priority.
  - The active player's half is highlighted. In any combat step (`#table.combat`) the phase bar turns red with a "Combat" tag, the combat steps sit on a red band and the table is tinted red, as Brett asked. The phase bar between the halves marks the current phase and has two stop toggles per phase: the upper one for the opponent's turn, the lower one for this player's. Defaults: own turn Main 1, Blockers, Main 2; opponent's turn Attackers, Blockers, End step. Stops are remembered per seat in `localStorage` and sent with the auto-pass setting.
  - The side panel: the decision panel (lit up when this player must act, with the prompt, the card it is about, chosen items and buttons), the stack (spells as cards; abilities as dashed purple tiles with a small source card; a triggered ability's tile has an "Always yield" chip, lit when on), and settings: Auto-pass (Off / If only mana abilities / If no actions) beside the Yield all switch, then the Hold priority switch, then (when there are any) the abilities the player always yields to, as chips that switch it off when clicked. The chip and the list change at once on a click. The deck picker and Restart are temporary playtest controls (Brett, 2026-11-28): they sit in their own dashed "Playtest only" panel (`#playtest`) below the settings, which are the permanent part. The space bar works while a switch or the Auto-pass list has focus (only text fields keep it). The stack takes all the space between the decision panel and the settings, and scrolls. The log is a popup (like a graveyard), opened by the understated "Game log" link in the stack's header; it follows the game while open and opens at the newest line.
  - Target lines (as in Endstep, in our cyan): each stack item with targets has a curved line from its left edge to each target (the top of a card on the battlefield, a player's name, or a spell on the stack), with the item's place on the stack (1 is the top) in a ring at both ends. They are an SVG overlay (`#arrows`, under popups) redrawn after each render and when the board, the decision panel or the stack scroll moves.
  - Block lines: each blocker is joined to the attacker it blocks by a straight blue line (`path.block` in `#arrows`), from the blocker's edge facing the attacker to the attacker's facing edge, with a dot at each end.
  - When the prompt offers cards in the player's hand (`selection.cards`, as for discarding or exiling from the hand, not casting), the hand gets the class `choosing` and is lit up with the decision panel's gradient and ring, from just below the pile labels.
  - Hovering any card shows a large preview at once, with its state (damage, counters, combat). It hides when the pointer leaves the card, when the card is removed (cast from the hand) and when a popup opens.
  - Every question from the engine is a popup over the board: cards are shown as cards and picked by clicking; revealed cards that can't be chosen are dimmed; the dual list (scry and the like) has two piles and arrows for order, and the cards in the ordered pile can be dragged into place (pointer events, so touch works too; a gold bar shows where the dragged one lands). Simultaneous triggered abilities ("Select order for simultaneous abilities", and the "Reorder" version when the order was set before) are one row of tiles, left to right in the order they resolve: the first tile says "Resolves first, goes on the stack last, on top", the last "Resolves last, goes on the stack first" (Forge's first in the list goes on the stack last; Brett found them vertical and undraggable, 2026-11-28). "Hide" collapses a popup to look at the board. Clicking a graveyard or exile pile shows its cards.
  - Emblems are shown at the end of their owner's back row, at permanent size, as Brett asked (so they aren't forgotten; by the rules they are in the command zone). Each sits in an `.emblem-slot` with `data-zone="Command"` and has its picture ("TBLD Player One.png" and so on in `res/tbld/pics/`). Clicking your own emblem uses it, without an "Exile Player One?" question (`HumanCostDecision`, for an emblem exiling itself from the command zone). Other command-zone cards are in the player bar under "Effects". An effect (such as Searing Touch's "can't gain life", or the one Player Three's emblem leaves) is shown as the art box of the card that made it (the snapshot marks it `effect` and gives it that card's picture, `BrowserSeat.sourceImageUrl`; the crop was measured on TBLD Searing Touch), and hovering it shows its art and text.
  - Elements carry `data-*` attributes and classes that the browser tests rely on (`data-zone`, `data-row`, `data-id`, `.selectable`, `.chosen`, `.tapped`, `.tags`, `#dialog[data-need]`, `.opt`, `.picked`, `.primary`).
- `forge-gui-desktop/src/main/java/forge/view/Main.java`: the command-line mode `tbld [port]` runs the server (default port 8080). `forge-gui-desktop/src/main/config/tbld-server.cmd` is the Windows launcher in the packaged build.

Next steps, in order: the chess clock (on the server: a player's time runs while the engine waits for that player's decision); lobby and deck import, merged with the TBLD site's card browsing and deck sharing; hosting.

Known issue: after an action, the previous buttons stay visible for about 250 ms (Forge's `awaitNextInput` delay); the client disables them once pressed, so this no longer passes priority twice.

## Building and running

Requires JDK 17 or newer and Maven. On Brett's PC, Maven is at `C:\Users\Tumbles\tools\apache-maven-3.9.16\bin\mvn.cmd` (not on PATH).

- To build and test one module without the installer, add `-pl forge-gui-desktop -am` (without `-am`, Maven cannot resolve the `${revision}` parent version).
- The packaged server locks its jar on Windows: stop it before rebuilding the package.

- Build the desktop package: `mvn -B -P windows-linux install -DskipTests -T 1C`
- The runnable package is `forge-installer/target/forge-installer-<version>/`. Run the server from that folder: `java -jar forge-gui-desktop-<version>-jar-with-dependencies.jar tbld 8080` (or `tbld-server.cmd`), then open `http://localhost:8080/` in two tabs and choose a seat in each.
- Restart the server after each rebuild.
